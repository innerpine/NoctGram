# NoctGram для Android

Нативный клиент на Kotlin и Jetpack Compose для существующего сервера https://noctgram.com — тот же API, что у iOS-приложения (`mobile/ios`, ветка `markdev/noctgram-ios-*`). Android 8.0 (API 26) и новее. Идентификатор приложения — `com.noctgram.app`.

## Что есть в базе

- Вход по одноразовому коду из письма (`/api/auth/start` → `/api/auth/verify`), первичная настройка имени и юзернейма, выход.
- Нижние вкладки: «Лента», «Сообщения» (пока заглушка), «Профиль».
- Лента «Для вас» и «Подписки»: текст, блок кода, фото, опросы (только результаты), отметка 18+ скрывает фото до нажатия, лайки, догрузка страниц, обновление жестом.
- Свой профиль: обложка (включая «Жидкое» — пока статичная размытая аватарка), аватар, юзернеймы, анонимный номер, описание, счётчики и свои публикации.

Чаты, публикация постов, комментарии, кошелёк, Маркет, видео и push-уведомления ещё не перенесены — для них пока остаётся сайт.

## Как устроено

Сторонних библиотек в приложении нет, кроме AndroidX и Compose: сеть — `HttpURLConnection`, JSON — `org.json`, шифрование — Android Keystore.

- `NoctApi.kt` — клиент сервера. Один зашитый HTTPS-адрес, только пути `/api/…`, без редиректов, ответы ограничены по размеру (8 МБ JSON, 25 МБ медиа). Ошибки сервера приходят как `ApiException` с русским текстом. Ответ 401 (кроме шагов входа) стирает сессию на устройстве.
- `Session.kt` — сессия. Сохраняются только два cookie сервера (`noct_session`, `noct_email_challenge`) и только если они `Secure`, `Path=/`, с токеном из 64 hex-символов и сроком жизни. На диске они лежат зашифрованными ключом AES-GCM из Android Keystore; файл исключён из резервных копий. Нечитаемые данные означают просто «не вошёл».
- `App.kt` — состояние входа и каркас с вкладками. `Auth.kt`, `Feed.kt`, `Profile.kt` — экраны. `Ui.kt` — тема из `DESIGN.md`, общие компоненты и загрузка картинок (медиа отдаётся только вошедшему аккаунту, поэтому идёт через `NoctApi`).

Осознанные упрощения помечены в коде комментариями `ponytail:` — кэш картинок только в памяти, нет видеоплеера, «Жидкое» статичное.

## Сборка

Локально нужны JDK 17+ и Android SDK (платформа 35, build-tools 35). Путь к SDK — в `local.properties` (`sdk.dir=C:/Android/Sdk`), файл в git не попадает.

```sh
cd mobile/android
./gradlew testDebugUnitTest assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка с отладочной подписью: её можно поставить на любой телефон, разрешив установку из неизвестных источников. Для публикации нужна release-сборка с собственным ключом — его в репозитории нет и быть не должно.

В GitHub Actions сборку делает `.github/workflows/android-apk.yml`: при пуше в ветки `markdev/noctgram-android-*`, если затронута папка `mobile/android/`, или вручную. Артефакт `NoctGram-Android` содержит APK и хранится 7 дней.

## Проверки

`NoctApiTest` без сети и без устройства проверяет разбор и отбор cookie, запрет выхода за пределы `/api/` своего адреса, сохранение и восстановление сессии, выход по отклонённой сессии (и его отсутствие при неверном коде), тексты ошибок и отказ от не-JSON ответов. Вход на настоящем телефоне, лента и профиль проверяются вручную.
