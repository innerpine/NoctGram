# NoctGram для Android

Нативный клиент на Kotlin и Jetpack Compose для существующего сервера https://noctgram.com — тот же API, что у iOS-приложения (`mobile/ios`, ветка `markdev/noctgram-ios-*`). Android 8.0 (API 26) и новее. Идентификатор приложения — `com.noctgram.app`.

## Что есть

- Вход по одноразовому коду из письма (`/api/auth/start` → `/api/auth/verify`), первичная настройка имени и юзернейма, выход.
- Плавающая панель вкладок в духе Telegram: «Лента», «Чаты» с бейджем непрочитанного, «Профиль» с аватаром аккаунта.
- Лента «Для вас» и «Подписки»: текст, блок кода, фото, результаты опросов, 18+ скрывает фото до нажатия, лайки, иконка комментариев, догрузка и обновление жестом. Автор открывается по нажатию.
- Новая публикация: текст, блок кода с языком, до четырёх фото из системной галереи, опрос на 2–6 ответов, отметка 18+.
- Комментарии: последняя страница, догрузка предыдущих, ответ.
- Профили, свой и чужие: обложка (включая «Жидкое» — пока статичная размытая аватарка), оформление Premium (палитра, градиент имени, значки, текст вокруг аватара, Chrome Flow, фон карточки), юзернеймы и анонимный номер в цвете профиля, присутствие, описание. Счётчики кликабельны: подписчики и подписки открывают списки, публикации прокручивают к постам. Подписка и «Написать».
- Редактирование своего профиля (имя, описание, аватар, обложка или «Жидкое») и экран «Дизайн» с живым предпросмотром — те же настройки, что на сайте; сохранение требует Noct Premium.
- Чаты: общий список личных диалогов и групп, переписка с опросом сервера раз в три секунды, отметки прочтения, ответы и вложения в ленте сообщений, отправка текста, а в личных диалогах ещё и фото. Секретные чаты показываются, но читаются только на сайте.

Кошелёк, Маркет, подарки, видео, реакции, голосование в опросах, поиск, создание групп и push-уведомления ещё не перенесены — для них пока остаётся сайт.

## Как устроено

Сторонних библиотек в приложении нет, кроме AndroidX и Compose: сеть — `HttpURLConnection`, JSON — `org.json`, шифрование — Android Keystore.

- `NoctApi.kt` — клиент сервера. Один зашитый HTTPS-адрес, только пути `/api/…`, без редиректов, ответы ограничены по размеру (8 МБ JSON, 25 МБ медиа). Ошибки сервера приходят как `ApiException` с русским текстом. Ответ 401 (кроме шагов входа) стирает сессию на устройстве.
- `Session.kt` — сессия. Сохраняются только два cookie сервера (`noct_session`, `noct_email_challenge`) и только если они `Secure`, `Path=/`, с токеном из 64 hex-символов и сроком жизни. На диске они лежат зашифрованными ключом AES-GCM из Android Keystore; файл исключён из резервных копий. Нечитаемые данные означают просто «не вошёл».
- `App.kt` — состояние входа, стек открытых экранов и панель вкладок. Экраны: `Auth.kt`, `Feed.kt`, `Compose.kt` (публикация и комментарии), `Profile.kt` (профиль и списки подписок), `ProfileEdit.kt` (редактирование и дизайн), `Chats.kt`. `Ui.kt` — тема из `DESIGN.md`, иконки, оформление Premium (`Look`, `DisplayName`, `ProfileAvatar`) и загрузка картинок: медиа отдаётся только вошедшему аккаунту, поэтому идёт через `NoctApi`.

Осознанные упрощения помечены в коде комментариями `ponytail:` — кэш картинок только в памяти, нет видеоплеера, «Жидкое» статичное.

## Сборка

Локально нужны JDK 17+ и Android SDK (платформа 35, build-tools 35). Путь к SDK — в `local.properties` (`sdk.dir=C:/Android/Sdk`), файл в git не попадает.

```sh
cd mobile/android
./gradlew testDebugUnitTest assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка с отладочной подписью: её можно поставить на любой телефон, разрешив установку из неизвестных источников. Для публикации нужна release-сборка с собственным ключом — его в репозитории нет и быть не должно.

В GitHub Actions сборку делает `.github/workflows/android-apk.yml`: при пуше в ветки `markdev/noctgram-android-*`, если затронута папка `mobile/android/`, или вручную. Артефакт `NoctGram-Android` содержит APK и хранится 7 дней.

## Проверки

`NoctApiTest` без сети и без устройства проверяет загрузку файлов (multipart, привязка к чату, отказ от небезопасных имён и типов), разбор и отбор cookie, запрет выхода за пределы `/api/` своего адреса, сохранение и восстановление сессии, выход по отклонённой сессии (и его отсутствие при неверном коде), тексты ошибок и отказ от не-JSON ответов. Вход на настоящем телефоне, лента и профиль проверяются вручную.
