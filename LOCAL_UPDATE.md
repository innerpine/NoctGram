# Обновление локальной версии

Ветка `main` содержит общую версию приложения: чат, подарки и бусты, адаптацию для телефона, SoundCloud и закрытый Cloudflare preview. Локальный запуск выбирается по умолчанию. `NOCT_PREVIEW_CONFIG` нужен только при отдельной сборке общего сервера.

## Существующая рабочая копия

1. Остановите локальный сервер. Сохраните свои незакоммиченные изменения и резервную копию `.wrangler/state`, `.env` и, если есть, `.dev.vars`. База и файлы находятся в `.wrangler/state`; Git их не переносит.
2. Получите изменения `main` обычным merge/pull, сохранив собственные коммиты. Для чистой копии без отдельной ветки разработки: `git pull --ff-only origin main`, затем `npm ci`.
3. Если база уже обновлена до `0028_chat_storage_guards`, но ещё не содержит `music_app_tokens` и столбец `music_imports.localPlaylistId`, примените только две новые миграции:

   ```sh
   npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0029_music_app_tokens.sql
   npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0030_imported_soundcloud_playlists.sql
   ```

   Уже применённую миграцию не запускайте повторно. Для более старой базы сначала примените отсутствующие миграции в порядке `drizzle/meta/_journal.json`. Для совершенно новой базы применяются все записи этого журнала: числовой порядок имён файлов не заменяет порядок журнала.
4. Сохраните текущий `MUSIC_TOKEN_KEY`: он нужен для расшифровки существующих музыкальных подключений. Для поиска и прямого воспроизведения SoundCloud на сервере также нужны `SOUNDCLOUD_CLIENT_ID` и `SOUNDCLOUD_CLIENT_SECRET`. Секреты задаются отдельно в локальном окружении, их нет в Git. Подключение личного аккаунта требует зарегистрированного у SoundCloud callback, соответствующего текущему адресу; не меняйте callback общего сайта ради локального теста.
5. Запустите `npm run dev` и откройте `http://localhost:3000`. Выбор основного и тестового аккаунтов: `http://localhost:3000/__dev/accounts`.

## Две среды

Локальная база и облачная D1 независимы. Переписка, файлы и плейлисты, созданные в одной среде, не появляются автоматически в другой. Обновление исходников не должно заменять ни одну из этих баз. Для возвращения на общий сайт достаточно открыть его адрес после восстановления доступа; повторный импорт локальных данных поверх общей базы не нужен.

Настройка общего сервера и перенос в новую пустую базу описаны в [SHARED_PREVIEW.md](SHARED_PREVIEW.md). Обычный локальный запуск не использует удалённую D1 и не расходует её суточный лимит.
