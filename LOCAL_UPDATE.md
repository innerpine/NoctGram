# Обновление локальной версии

## Noct Market — 21 сентября

Примените `0048_market.sql`, предварительно сохранив резервную копию `.wrangler/state`:

```sh
npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0048_market.sql
```

Миграция только добавляет таблицы `market_numbers`, `market_listings` и триггер резервирования системных юзернеймов; существующие данные не меняются. Лоты выпускает администратор из кабинета. Подробнее — [MARKET.md](MARKET.md).

## Объединение от 10 сентября

В `main` объединены обновления чатов, мини-профилей, видео, музыки и приватности с группами, секретными чатами, архивом, Premium-эмодзи и реальными платежами. Обновите код и зависимости: `git pull --ff-only origin main`, затем `npm ci`. Если есть свои незакоммиченные изменения, сначала сохраните их и объедините ветки обычным merge.

Перед обновлением базы остановите сайт, бота и фоновые задания и скопируйте `.wrangler/state`. **Выбирайте отсутствующие миграции по полному имени, а не номеру:** разные ветки уже использовали префиксы 0031–0033. Имена и SQL ранее применённых миграций сохранены; общий порядок для новой базы находится в `drizzle/meta/_journal.json`.

- Если ваша база уже содержит наши группы, архив и платежи вплоть до `0034_payment_checkout_guards`, примените только `0031_repeat_music_listens.sql`, `0032_presence_privacy.sql`, `0033_profile_background.sql`.
- Если база друга уже обновлена до `0033_profile_background` из прежней `main`, примените только `0031_security_boundaries.sql`, `0032_chat_rooms.sql`, `0033_archive_commerce.sql`, `0034_payment_checkout_guards.sql` — именно в таком порядке.
- Для промежуточной версии сверяйте схему: `music_listens.plays` и `music_sessions.counted` — повторные прослушивания; `user_presence_privacy` и `user_presence_exceptions` — приватность сети; `profile_appearance.background` — оформление фона; `chat_rooms` — группы; `payment_orders` и `direct_chat_archives` — платежи и архив; `payment_orders.checkedAt` и `precheckoutId` — финальная миграция платежей. Частично выполненную миграцию сначала разберите на копии базы.

Каждый выбранный файл запускается один раз:

```sh
npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/ИМЯ_ОТСУТСТВУЮЩЕЙ_МИГРАЦИИ.sql
```

Не используйте максимальный номер или timestamp для определения отсутствующих миграций из другой ветки. Данные, `.env` и состояние бота через Git не передаются. После обновления запустите `npm run dev`, при необходимости `npm run dev:bot` и `npm run dev:jobs`. Покупки и ключи бота описаны в [COMMERCE.md](COMMERCE.md).

Ветка `main` содержит общую версию приложения: чат, подарки и бусты, адаптацию для телефона, SoundCloud и закрытый Cloudflare preview. Локальный запуск выбирается по умолчанию. `NOCT_PREVIEW_CONFIG` нужен только при отдельной сборке общего сервера.

## Существующая рабочая копия

1. Остановите локальный сервер. Сохраните свои незакоммиченные изменения и резервную копию `.wrangler/state`, `.env` и, если есть, `.dev.vars`. База и файлы находятся в `.wrangler/state`; Git их не переносит.
2. Получите изменения `main` обычным merge/pull, сохранив собственные коммиты. Для чистой копии без отдельной ветки разработки: `git pull --ff-only origin main`, затем `npm ci`.
3. Если база уже обновлена до `0028_chat_storage_guards`, но ещё не содержит `music_app_tokens` и столбец `music_imports.localPlaylistId`, примените только две новые миграции:

   ```sh
   npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0029_music_app_tokens.sql
   npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0030_imported_soundcloud_playlists.sql
   ```

   Уже применённую миграцию не запускайте повторно. Для более старой базы сначала примените отсутствующие миграции в порядке `drizzle/meta/_journal.json`. Для совершенно новой базы применяются все записи этого журнала: числовой порядок имён файлов не заменяет порядок журнала.

4. Сохраните текущий `MUSIC_TOKEN_KEY`: он нужен для расшифровки существующих музыкальных подключений. Для поиска и прямого воспроизведения SoundCloud на сервере также нужны `SOUNDCLOUD_CLIENT_ID` и `SOUNDCLOUD_CLIENT_SECRET`. Секреты задаются отдельно в локальном окружении, их нет в Git. Подключение личного аккаунта требует зарегистрированного у SoundCloud callback, соответствующего текущему адресу; не меняйте callback общего сайта ради локального теста.
5. Запустите `npm run dev` и откройте `http://localhost:3000`. Выбор основного и тестового аккаунтов: `http://localhost:3000/__dev/accounts`.

## Чарты и повторные прослушивания

После обновления до чартов с повторными прослушиваниями примените новую миграцию `0031_repeat_music_listens` (один раз):

```sh
npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0031_repeat_music_listens.sql
```

Она добавляет счётчик повторов и отметку подтверждённого прослушивания. Прежние результаты чартов сохраняются. Сначала обновите базу, затем запускайте новую версию сервера.

## Видимость статуса сети

Перед запуском версии с приватностью статуса сети примените `0032_presence_privacy` один раз:

```sh
npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0032_presence_privacy.sql
```

Миграция добавляет настройки видимости и исключения. По умолчанию статус видят все; существующие данные сохраняются.

## Две среды

Локальная база и облачная D1 независимы. Переписка, файлы и плейлисты, созданные в одной среде, не появляются автоматически в другой. Обновление исходников не должно заменять ни одну из этих баз. Для возвращения на общий сайт достаточно открыть его адрес после восстановления доступа; повторный импорт локальных данных поверх общей базы не нужен.

Настройка общего сервера и перенос в новую пустую базу описаны в [SHARED_PREVIEW.md](SHARED_PREVIEW.md). Обычный локальный запуск не использует удалённую D1 и не расходует её суточный лимит.
