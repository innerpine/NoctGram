# Noct Gifts: общий аккаунт NoctGram

Мини-апп использует основной баланс `star_transfers` и подарки `received_gifts`. Локальные начисления, демонстрационные результаты и вход с выдуманным профилем удалены. Вход — через проверенный Telegram `initData` бота Noct Gifts и существующую привязку Telegram к NoctGram.

## Выкладка на noctgram.com

Постоянный адрес мини-аппа: **https://noctgram.com/drop/**. Он включён в стандартную сборку NoctGram, использует основные API и исходные изображения подарков; отдельный туннель и сервер для рабочего адреса больше не требуются. React и ReactDOM версии 18.3.1 поставляются локально с проверенными хешами исходного runtime. В действующем drop-боте задайте `NOCT_GIFTS_APP_URL=https://noctgram.com/drop/` и перезапустите его единственный polling-процесс. Нижняя кнопка меню задаётся через `setChatMenuButton`; старые сообщения сохраняют свои прежние ссылки.

Пункты 4–5 ниже описывают альтернативный отдельный стенд. Для основной выкладки используйте `/drop/` и существующую базу.

1. Обновить код из main. На **основной базе NoctGram** применить новую миграцию `drizzle/0054_noct_gifts_live.sql` перед запуском обновлённого приложения. Она добавляет таблицу расходования подарков и защитные триггеры; существующие деньги и подарки не переносятся в другую базу.
2. На сервере NoctGram задать секрет `NOCT_GIFTS_BOT_TOKEN` — токен @noctgramdrop_bot. Он должен совпадать с токеном в настройках drop-бота. Токен не хранится в Git.
3. Собрать и запустить NoctGram штатным способом. Новые маршруты перечислены ниже. Пока они не выложены, мини-апп показывает ошибку подключения и ничего не начисляет локально.
4. Разместить папку `noct-gifts/` в корне отдельного домена за HTTPS. В её серверном окружении задать `NOCTGRAM_API_ORIGIN=https://noctgram.com` и `PUBLIC_ORIGIN` — точный публичный адрес мини-аппа без пути. Запуск: `node --env-file=.env server.mjs` из этой папки. Сервер слушает `127.0.0.1:4186`; HTTPS reverse proxy должен сохранять исходный Host (в nginx: `proxy_set_header Host $host;`), иначе публичные запросы будут отклонены.
5. Заполнить локальный `bot/.env.drop` по `bot/drop.env.example`. `NOCT_GIFTS_APP_URL` — полный HTTPS-адрес `Noct%20Gifts%20App.dc.html`. Выполнить `node --env-file=bot/.env.drop bot/drop-setup.mjs`, затем запустить `node --env-file=bot/.env.drop bot/drop.mjs` под менеджером процессов. Одновременно должен работать один polling-процесс этого бота.
6. Для проверки открыть мини-апп из Telegram с привязанным аккаунтом. Выигранный подарок должен сразу появиться в разделе подарков профиля NoctGram. Обновление уже открытого профиля выполняется обычным обновлением списка/страницы.

Для Cloudflare D1 миграция выполняется штатной командой проекта на binding DB с конфигурацией **основной** базы. Локальный пример: `npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0054_noct_gifts_live.sql`. Локальная команда не обновляет основной сервер.

`NOCT_GIFTS_PAYMENTS_DISABLED=1` отключает создание счетов для отдельной локальной базы; на рабочем сервере с основной базой флаг должен отсутствовать или быть 0. Пополнение использует существующий платёжный бот NoctGram. Не направлять локальные заказы в бот, работающий с другой базой. Тестовые начисления NoctGram должны быть выключены в рабочем окружении (`NOCT_STARS_TEST_MODE=0`, `NOCT_BOT_TEST_MODE=0`).

## API

Все запросы — POST JSON с `initData`; ответы приватные и не кешируются. Сервер проверяет подпись, срок 1 час, текущую привязку, блокировки и отзыв сеансов. Изменяющие операции дополнительно проверяют ограничения и баланс внутри транзакции.

- `/api/noct-gifts/account`: `{initData,before?}`. Общий профиль, баланс, подарки с пагинацией, история, пакеты оплаты, серверный каталог `games` и `capabilities`.
- `/api/noct-gifts/avatar`: `{initData}`. Изображение текущего аватара привязанного профиля: WebP 384 px или исходный файл. Telegram-миниапп получает его без cookie сайта и показывает через временный Blob URL; произвольный ID файла передать нельзя.
- `/api/noct-gifts/topup`: `{initData,sku,key,acceptedTerms:true}`. Счёт существующего платёжного бота. Начисление только после подтверждённой оплаты.
- `/api/noct-gifts/case`: `{initData,key,caseId,version,count?}`. `count` — число 1, 3, 5 или 10 (по умолчанию 1). Цена и вероятности из серверного каталога; одна транзакция проверяет полную сумму, списывает Stars за все открытия и создаёт отдельный подарок для каждого результата.
- `/api/noct-gifts/upgrade`: `{initData,key,receiptId,targetGiftId,version}` либо `{initData,key,receiptIds,targetGiftId,version}` для пакета. Массив содержит 1, 3, 5 или 10 разных экземпляров; `receiptId` и `receiptIds` одновременно запрещены. Все исходные подарки должны быть обычными, доступными и дешевле одной выбранной цели. Каждая попытка имеет собственный шанс и результат; все исходные подарки расходуются атомарно. Noct Stars не списываются, в том числе при нулевом балансе.

Ключ операции — 16–120 латинских букв, цифр, `_` или `-`. При таймауте повторять **тот же ключ и параметры**: сервер вернёт сохранённый результат без повторного списания. Браузер сохраняет незавершённый запрос по владельцу в sessionStorage. Новый запрос недоступен до выяснения предыдущего результата.

Ответ игры: `{userId,operation,balance,gift}`. Подарок уже записан до начала анимации. Анимации и пропуск прокрутки не влияют на результат. `gift.available=false` означает, что ранее выданный экземпляр уже израсходован или продан: повтор ответа не возвращает его в инвентарь. Если экземпляр стал коллекционным, ответ сохраняет актуальные коллекционные атрибуты.

Для пакета ответ дополнительно содержит `results: [{operation,gift}, ...]` в порядке попыток и `gifts` со всеми выигранными подарками. Верхние `operation.count` и `operation.price` показывают количество и общую стоимость; внутри `results` стоимость каждой попытки отдельная. `gift` верхнего уровня относится к первой попытке для совместимости. Версия пакетного каталога — `2026-09-15-3`. Каждый выигрыш сохраняет собственную платёжную запись и возможность продажи; новая миграция поверх `0056` не нужна. Ошибка записи любой попытки откатывает весь пакет.

## Подарки и цены

Идентификаторы, названия, изображения и стоимость подарков берутся из каталога NoctGram. Обычным подаркам не приписываются фиктивные коллекционные номера. В составе кейсов явно разрешены восемь подарков из дизайна, включая архивные; их прямая покупка в основном каталоге не меняется.

Цены кейсов: Лунный 75, Орбита 150, Затмение 320, Полночь 60 Noct Stars. Точные веса — `lib/noct-gifts-catalog.ts`; версия условий обязательна в запросах. Начиная с версии `2026-09-15-2`, апгрейд расходует только подарок, дополнительная плата в Stars равна нулю. С версии `2026-09-15-4` шанс: округлённое отношение стоимости исходного подарка к цели × 110, в пределах 3–95%. В кейсах повышена вероятность более дорогих подарков, цены сохранены. Уже подтверждённые попытки при повторе возвращают прежний шанс и результат; запрос с устаревшей версией каталога не начинает новое списание.

Запись `gift_risk_upgrade` с суммой 0 сохраняет результат и защищает от повторного использования подарка, не меняя кошельки участников. Миграция 0056 разрешает продажу выигрыша от такой попытки. Старые оплаченные операции сохраняются; повтор их ключа возвращает прежний результат без новой оплаты. Новая попытка со старой версией условий требует обновления каталога.

Выигрыш — обычный подарок NoctGram. Его можно продать на основном сайте через обычное меню подарка: комиссия 15%, зачисление `floor(стоимость подарка × 0.85)` Noct Stars на общий баланс. Для дропа используется `operation.giftPrice`, зафиксированная сервером при выдаче, а не плата за кейс или попытку апгрейда. Для ранее выданных дропов без этого поля миграция 0055 сохраняет значения исходного каталога версии `2026-09-15-1`. Обычные купленные подарки по-прежнему продаются за 85% исходного платежа.

Гарантированное улучшение в коллекционный за 25 Stars на основном сайте остаётся отдельной функцией; коллекционные подарки за Stars не продаются. Продажа и рискованный апгрейд не могут одновременно расходовать один экземпляр. Проданный или расходованный подарок исключается из профиля и миниаппа; история получения сохраняется, повтор запроса продажи не начисляет звёзды второй раз.

## Проверки

`node --test tests/noct-gifts-account.test.mjs tests/gifts.test.mjs tests/gift-upgrades.test.mjs tests/combined-migrations.test.mjs`

`node --test noct-gifts/prototype.test.mjs noct-gifts/account-bridge.test.mjs noct-gifts/server.test.mjs`

`node --test tests/drop-bot.test.mjs tests/bot.test.mjs`

Проверяются общая выдача, параллельные запросы, недостаточный баланс, полный rollback, одинаковый ключ после потери ответа, расходование подарка, привязка/блокировки, восстановление после перезагрузки и отсутствие локальных начислений.
