# Закрытый общий тест

Общий сервер работает в Cloudflare Workers с одной базой D1 и закрытым хранилищем R2 Standard. Разработка по-прежнему ведётся в отдельных локальных копиях. Git переносит код; данные общей версии меняются только на общем сервере.

## Вход

Для этой версии используется `NOCT_AUTH_MODE=access`. Cloudflare Access отправляет одноразовый код на разрешённую почту. Приложение дополнительно проверяет подпись RS256, срок действия, issuer, audience, тип токена и явное соответствие почты внутреннему ID пользователя. Заголовки локального входа и старые сессионные cookie не могут заменить эту личность.

Владелец привязывается к существующему ID, поэтому сохраняются профиль, права, переписка, подарки и плейлисты. Новый участник проходит настройку своего профиля. Тестовые профили сохраняются как записи; для входа в ещё один профиль нужна отдельная разрешённая почта. Для выхода используется Cloudflare Access logout.

## Бесплатные ограничения

Использовать Workers Free, D1 Free, Zero Trust Free и R2 Standard. Не включать Workers Paid, Infrequent Access, публичный R2-домен или платные дополнения.

На 9 сентября 2026 года R2 включает 10 ГБ хранилища, 1 млн операций Class A и 10 млн Class B в месяц бесплатно. R2 тарифицирует превышение; это не тариф с банковским запретом любых списаний. Лимиты относятся ко всему аккаунту Cloudflare, включая другие проекты и ручные операции.

В режиме Access приложение ограничивает обращения к R2: 10 000 Class A и 200 000 Class B в календарный месяц UTC; суммарно до 3 ГиБ загруженных данных за весь тест, включая исходный перенос. Повторные и неудачные загрузки тоже расходуют резерв; удаление файлов не восстанавливает его. Это консервативная защита бюджета, включая оставшиеся после ошибки объекты. Счётчики хранятся в D1 `auth_limits`; их нельзя сбрасывать для обхода ограничений. Неизвестные потоки и multipart-загрузки запрещены в этом режиме. При достижении лимита операция прекращается до обращения к R2.

При превышении бесплатных лимитов Workers/D1 запросы могут временно перестать работать. Фактическую загрузку CPU проверять после публикации: лимит Workers Free — 10 мс. Платные внешние сервисы, звонки через TURN и интеграции подключаются отдельно с учётом их тарифов.

Источники: [Workers](https://developers.cloudflare.com/workers/platform/limits/), [D1](https://developers.cloudflare.com/d1/platform/pricing/), [R2](https://developers.cloudflare.com/r2/pricing/).

## Сборка и публикация

Обычные `npm run dev` и `npm run build` сохраняют существующий режим Sites и локальные аккаунты. Для отдельной общей версии создать **игнорируемый** `work/preview.json` с именем Worker, account ID, реальными привязками `DB` и `FILES` и переменными:

- `NOCT_AUTH_MODE`: `access`.
- `NOCT_ACCESS_TEAM_DOMAIN`: точный HTTPS-домен команды `*.cloudflareaccess.com`.
- `NOCT_ACCESS_AUD`: audience созданного приложения Access.
- `NOCT_ACCESS_USERS`: JSON вида `{"owner@example.com":{"userId":"existing_owner_id"},"friend@example.com":{"userId":"new_friend_id"}}`, максимум три разных пользователя.

Access должен защищать только этот Worker, включая все его адреса. Разрешающее правило содержит точные адреса участников; без Everyone, Bypass или общих доменных масок. По умолчанию прочим пользователям отказано. Для почтового кода включить One-time PIN.

В PowerShell установить `$env:NOCT_PREVIEW_CONFIG='work/preview.json'`, затем выполнить `npx tsc --noEmit`, `npm run lint`, `node --test tests/*.test.mjs`, `npm run build`. Сборка использует `worker/shared-preview.ts` и `assets.run_worker_first=true`: защита выполняется и перед выдачей статических файлов. При неполной настройке приложение возвращает 403, не выдавая данные.

Публиковать `dist/server/wrangler.json` через Wrangler. Секреты передавать через `wrangler secret bulk` из игнорируемого файла, никогда не включать их в исходники или клиентскую сборку. Для сохранённых музыкальных подключений нужен исходный `MUSIC_TOKEN_KEY`; OAuth redirect URL должен указывать на общий HTTPS-адрес.

## Перенос данных

1. `scripts/export-local-preview.mjs <исходная папка> <sqlite-файл> <новая приватная папка>` создаёт согласованную копию SQLite, копию R2 и отдельные объекты с SHA-256. Проверяет целостность базы, связи и наличие вложений. Исходники и работающая локалка не меняются. На время переноса не загружать и не удалять файлы; если данные менялись, повторить экспорт в новую папку перед окончательным переключением.
2. `scripts/prepare-preview-import.mjs <папка копии>` создаёт `import.sql` и контрольные суммы таблиц. Сначала размещает строки, на которые ссылаются другие записи, включая ссылки внутри таблицы; циклические зависимости требуют отдельной обработки. Старые сессии и одноразовые коды входа не переносятся. Исходная резервная копия остаётся полной.
3. Импорт разрешён **только в подтверждённо пустую новую D1**, без DROP существующих таблиц. Не применять заново старые миграции поверх копии. Загрузить объекты в приватный R2 Standard под прежними ключами, сохранив метаданные, затем скачать и сравнить SHA-256.
4. Экспортировать удалённую D1 обратно, проверить все таблицы через `rowDigest` из скрипта импорта и `PRAGMA foreign_key_check`. Инициализировать `auth_limits` записью `preview:r2:uploaded-bytes`: размер всех перенесённых объектов; срок `Number.MAX_SAFE_INTEGER`.
5. Перед выдачей ссылки проверить, что запросы без входа и с поддельными заголовками не получают данные; разрешённые участники попадают в разные профили. Локальные резервные копии не удалять.

Все SQL-дампы, адреса участников, секреты, файлы пользователей и отчёты переноса хранить только в игнорируемых приватных папках. В Git попадают исходники и инструкция, без данных пользователей.
