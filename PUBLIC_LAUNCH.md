# Публичный Noctgram

Публичная версия работает на `https://noctgram.com`; `www` сохраняет путь и параметры и перенаправляет на основной HTTPS-адрес. Закрытый preview, его Worker и данные отделены от публичного окружения. Исходная база запуска — актуальная ветка `main` с изменениями комнат, архива, платежей и видеоплеера.

## Окружение и секреты

Используются Worker `noctgram-public`, D1 `noctgram-public` и закрытый R2 `noctgram-public-files`. Supabase хранит почтовую идентификацию, а профили, сообщения и файлы остаются в Cloudflare.

Итоговый JSON-конфиг и резервные копии хранятся в игнорируемом `work/`. Конфигурация содержит реальные привязки `DB`/`FILES`, `workers_dev: false`, `preview_urls: false`, оба custom domain и следующие переменные:

- `NOCT_DEPLOYMENT_TARGET=standalone`, `NOCT_AUTH_MODE=email`.
- `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` — URL проекта и publishable key. Административного ключа в приложении нет.
- При включённом SoundCloud: `SOUNDCLOUD_CLIENT_ID`, `SOUNDCLOUD_REDIRECT_URI=https://noctgram.com/api/music/services/soundcloud/callback`.
- В Worker secrets: `MUSIC_TOKEN_KEY`, `NOCT_JOBS_SECRET`, `SOUNDCLOUD_CLIENT_SECRET`.

Нельзя задавать `NOCT_AUTH_ALLOW_LOCAL_PROVIDER=1`. `worker/public.ts` при неверном почтовом окружении возвращает 503 до загрузки приложения, очищает заголовки Sites/preview/Access и оставляет авторизацию проверенной сессии Noctgram. Cron каждые 5 минут вызывает защищённый обработчик заданий.

## Сборка и выпуск

После проверок из [RELEASE_READINESS.md](RELEASE_READINESS.md), в PowerShell:

```powershell
$env:NOCT_PUBLIC_CONFIG = 'work/public.json'
$env:NOCT_PUBLIC_SECRET_NAMES = 'work/public-secret-names.json'
npm run build
npm run check:deployment -- --config dist/server/wrangler.json --target public --secret-names work/public-secret-names.json
npx wrangler secret bulk work/public-secrets.json --config dist/server/wrangler.json
npx wrangler deploy --config dist/server/wrangler.json
```

Каждый следующий шаг выполняется только после успешного предыдущего. Инвентарь секретов содержит только имена; значения — отдельно, вне Git. Перед deploy сверить точный Worker и привязки. Не направлять публичную сборку в preview. Для возвращения к обычной локальной сборке удалить обе переменные `NOCT_PUBLIC_*` из процесса. Не смешивать их с `NOCT_PREVIEW_CONFIG`.

## Перенос данных 11 сентября 2026

Перенесены 6 профилей, 93 сообщения, 9 публикаций и 19 файлов общим размером 20 986 255 байт. Сохранены ID, связи, оформление, подарки и плейлисты. Две существующие почтовые идентификации сопоставлены с прежними профилями; неиспользованное приглашение Access не создаёт профиль.

Перед импортом сделаны SQL-экспорт и локальная копия каждого R2-объекта. Файлы проверены SHA-256 до и после копирования. На локальной SQLite-копии применены отсутствовавшие миграции `0031_security_boundaries`, `0032_chat_rooms`, `0033_archive_commerce`, `0034_payment_checkout_guards`. Схема сопоставлена со свежей базой из всех 38 записей migration journal. После импорта повторный экспорт подтвердил количество и контрольные суммы данных всех 78 таблиц, целостность SQLite и внешние ключи. Временный Worker копирования файлов удалён.

Применённая граница схемы — все 38 записей `drizzle/meta/_journal.json` на исходном commit `a401dd9`; их теги и SHA-256 записаны в приватном `work/public-backup/schema-migrations.json`. В перенесённой базе нет журнала Drizzle: **не запускать повторно все старые миграции**. Перед следующей миграцией сверить эту границу, сделать новую резервную копию и проверить изменения на копии. Импорт первоначального snapshot поверх уже открытой публичной базы потеряет новые данные и запрещён.

Ключ шифрования музыкальных подключений выбран по успешной расшифровке сохранённых записей. OAuth callback SoundCloud переключён на публичный домен; подключение новых аккаунтов SoundCloud выполняется здесь. Перенесённые OAuth refresh tokens могут потребовать повторного подключения: два независимых окружения не должны одновременно обновлять одну копию токена.

## Почта и эксплуатация

В Supabase включены регистрация, подтверждение Email, шестизначный OTP на 300 секунд и минимум 60 секунд между повторными отправками. Для Magic Link и Confirm signup заданы кодовые письма. SMTP: Resend, `smtp.resend.com:465`, пользователь `resend`, отправитель `login@auth.noctgram.com`, имя Noctgram. Домен отправителя подтверждён; SPF/DKIM и DMARC настроены. SMTP-ключ ограничен отправкой с этого домена и хранится только в Supabase/приватной резервной копии.

На момент запуска Workers Paid активирован с базовой стоимостью $5/месяц; это не абсолютный предел счёта. Использование сверх включённых объёмов оплачивается отдельно. Supabase и Resend — бесплатные планы. Resend допускает 100 писем в день и 3 000 в месяц; лимит Supabase SMTP выставлен 100/час и не увеличивает дневную квоту Resend. Следить за фактическими квотами и расходами в кабинетах сервисов.

Проверка запуска включает HTTPS, загрузку JS/CSS, канонический redirect, anonymous session без Sites-входа, отказ поддельным identity-заголовкам и чужому Origin, закрытые API сообщений/загрузок, действующие привязки и отдельную защиту preview. Реальный почтовый вход проверяется отдельно: статус Delivered у SMTP и вход через форму Noctgram. Для существующего профиля вводится его прежняя почта; новый адрес ведёт в настройку нового аккаунта.

TURN и Web Push не были настроены в исходном preview и автоматически не появились после переноса. Успех HTTP-проверок не подтверждает звонки между разными сетями, push-доставку, реальную оплату или нагрузку 100 одновременных пользователей.

## Откат

Зафиксировать commit, ID Worker deployment и сохранённую схему. При регрессии кода вернуть предыдущую совместимую версию `noctgram-public`, сохранив текущие D1/R2. При необходимости временно закрыть публичный вход, не перенаправляя пользователей в чужую базу. Восстановление SQL/R2 — отдельная операция после оценки новых записей; резервная копия первоначального запуска не заменяет актуальный backup. Закрытый preview не служит автоматическим failover для публичных пользователей.
