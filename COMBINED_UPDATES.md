# Общая версия после объединения 7 сентября

Объединены музыкальная ветка `codex/music-section` (`e050cfa`) и последняя ветка друга `markdev/stars-topup-animation` (`3c9a3e6`). Последняя уже включает остальные обновления Markdev: истории, звонки, каналы, уведомления, оформление Premium, бота, перенос сохранённого в профиль и анимации Stars.

Музыка, новый плеер и его исправление после горячего обновления сохранены. В навигации есть «Музыка», а «Сохранённое» открывается из собственного профиля. История обоих разработчиков входит в merge-коммит.

## Как получить код

Сначала сохраните и закоммитьте свои незавершённые изменения. В своей рабочей ветке:

```powershell
git fetch origin
git merge origin/main
npm ci
```

Так новая общая версия объединяется с вашей работой. Не загружайте старую папку проекта поверх новой и не используйте принудительную отправку ветки.

## Как обновить существующую локальную базу

Остановите локальный сервер перед миграциями. Выполняйте команды из папки проекта. Локальная база, файлы и `.env` не передаются через GitHub.

Сохраните резервную копию базы в игнорируемой папке `work`:

```powershell
New-Item -ItemType Directory -Force work | Out-Null
npx wrangler d1 export DB --local --config wrangler.local.json --output work/before-combined-updates.sql
```

У двух веток были разные миграции с одинаковыми числовыми префиксами. Все исходные SQL-файлы оставлены без изменения; сравнивайте **полные имена**, а не только 0007/0008/0009. Журнал и снимки Drizzle теперь описывают общую последовательность из 14 миграций.

Если в вашей базе уже работала музыка из `e050cfa`, нужны только миграции друга:

```powershell
$pendingMigrations = @(
  '0007_organic_slipstream.sql',
  '0008_spotty_madame_web.sql',
  '0009_dazzling_eternity.sql',
  '0010_past_chat.sql'
)
```

Если в вашей базе уже работали все функции Markdev из `3c9a3e6`, нужны только музыкальные миграции:

```powershell
$pendingMigrations = @(
  '0007_perfect_radioactive_man.sql',
  '0008_polite_adam_destine.sql',
  '0009_ambiguous_polaris.sql'
)
```

После выбора **одного подходящего списка**:

```powershell
foreach ($migrationFile in $pendingMigrations) {
  npx wrangler d1 execute DB --local --config wrangler.local.json --file "drizzle/$migrationFile"
  if ($LASTEXITCODE -ne 0) { throw "Миграция не выполнена: $migrationFile" }
}
npm run dev
```

Если некоторые из этих миграций уже выполнялись, исключите их из списка. При неизвестном состоянии базы сначала проверьте её схему; не запускайте весь список повторно. Для новой пустой базы применяются все файлы по инструкции в CONTRIBUTING.md. Рабочая удалённая база этим объединением не изменяется.

Новые настройки перечислены в `.env.example`. Добавляйте только недостающие значения в свой `.env`, сохраняя существующие токены. Настройки Spotify, Яндекса, push, TURN и бота остаются индивидуальными. Тестовые пополнения и тестовая активация Premium по умолчанию выключены.

## Проверка объединения

`tests/combined-migrations.test.mjs` проверяет создание новой базы, обновление обеих прежних веток, сохранность аккаунта/коллекции/оформления, внешние ключи и соответствие снимков схеме. `drizzle-kit check` и `db:generate` подтверждают согласованность истории; дополнительных изменений схемы генератор не обнаруживает.

Проверки API выполняются в отдельной базе `work/features-qa`. Тестовые фикстуры не применяются к рабочим данным. Реальное воспроизведение Spotify и загрузка плейлистов Яндекса по-прежнему зависят от настройки аккаунтов и доступности сервисов.
