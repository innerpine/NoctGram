# Comments, text selection and email codes

Comments have an **Ответить** action, a cancellable composer quote and a stored
`replyTo` reference. Replies are grouped directly below their parent comment,
with chronological ordering among siblings and an indent capped at two levels
to keep narrow screens readable. A newly sent reply scrolls into view within the
discussion. Paging still loads comments chronologically; replies to unloaded
parents stay visible with their quote and join their parent when it is loaded.
The referenced comment must belong to the same post; blocked,
moderated, unregistered or deleted authors cannot be quoted. Quotes are resolved
at read time rather than stored as copies. Deleting a parent retains its replies
and shows an unavailable quote. Existing post visibility and write guards still
apply. The composer stays below a flexibly sized scrolling discussion.

Text selection no longer runs the chat text change/limit logic. On the previous
release an oversized restored draft caused a selection update to recursively
restore the previous state. Running the actual old listener with a 4,100-character
draft reached a 51-update safety cutoff from one selection event. The replacement
ignores selection-only updates, tags its own rollback, and lets old oversized
drafts be shortened. Profile text selection also does not activate profile links
or include the decorative animated SVG ring. The specific intermittent hang
reported while selecting a profile was not reproduced in the browser; this fix
eliminates the independently reproduced editor loop without claiming that every
possible browser hang has the same cause.

Email challenge timing now uses the server timestamp plus a monotonic elapsed
clock. Incorrect device time no longer disables a fresh code immediately.
Missing browser cookies, expired challenges, exhausted attempts and a changed
email in another tab have distinct messages. Provider failures no longer all
claim that a code expired. The configured Supabase OTP length (6), expiry (300
seconds), and both email templates were checked in its dashboard; both templates
contain a code, without a one-time sign-in URL. No real verification emails were
sent during testing. The user's reported mailbox/delivery sequence is unknown,
so its exact cause remains unconfirmed.

## Validation and release

- 535 automated checks passed, including reply privacy/deletion, real D1 email
  challenge tests, legacy draft selection/rollback, and profile link activation.
- TypeScript, lint and production build checked.
- Browser checks use isolated synthetic users/API responses, including replying,
  cancelling without losing text, profile selection and a device clock 2 hours
  ahead. No test comments were sent to production.
- Apply **only** `drizzle/0042_comment_replies.sql` to an existing public database.
  It adds one nullable column. Do not replay historical migrations: this public
  database predates a managed migration journal.
- A fresh public backup was validated locally: all 80 tables and 2,976 rows were
  preserved by the migration, foreign key/integrity checks passed, and its schema
  matched a database created from the full migration sequence.

## Threaded display follow-up

- Replies now follow their parent before the next top-level conversation.
- Loading an older parent regroups existing replies without duplicating them;
  deleting a parent keeps its descendants available with the unavailable quote.
- Iterative traversal handles long chains and malformed cycles without recursion.
  Seven focused checks cover these cases, sibling ordering and overlapping pages.
- The display update needs no database migration.
