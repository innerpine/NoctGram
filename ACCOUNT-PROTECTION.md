# Верификация, администрирование и защита аккаунтов

В «Модерация → Управление» администратор ищет пользователя по имени или любому юзернейму и выдаёт Stars, Premium, верификацию или роль модератора. Начальный администратор существующей локальной базы — Seedy с неизменяемым ID `local_seedy`. Юзернейм `root` сам по себе не даёт полномочий. Новые администраторы через интерфейс не назначаются.

Stars начисляются отдельной операцией `admin_grant`, запускают существующую анимацию пополнения и отражаются в истории. Допустимо 1–1 000 000 Stars за операцию. Premium выдаётся на 1–365 дней; действующий срок продлевается. Каждая выдача требует причины. Изменение и запись журнала выполняются одной транзакцией; повтор запроса не повторяет выдачу. Модераторы выдавать привилегии не могут. Stars и Premium выдаются личным аккаунтам, верификация доступна также каналам.

Верификация независима от Premium. Оригинальный PNG сохранён без изменений в `public/assets/noct-verified.png`; CSS использует luminance mask, чтобы сохранить чёрную корону и окрасить светлую часть в цвет профиля. Значок показывается рядом с именем; профиль получает русскую подпись NoctGram.

## Настройки аккаунта

«Редактировать → Аккаунт»: смена почты, резервные коды, выход со всех устройств, сведения о хранилище и удаление аккаунта.

- Вход по почте подтверждает доступ на пять минут. По истечении этого времени для смены почты, создания резервных кодов и удаления нужен новый OTP текущей почты. Смена почты дополнительно требует OTP нового адреса. Существующий `userId` сохраняется; остальные сессии и старые резервные коды отзываются.
- Восемь резервных кодов показываются только при генерации, их можно скачать. В базе хранятся только SHA-256 хеши. Каждый код однократный и действует год. Ссылка «Нет доступа к почте?» ведёт на `/recover`. Успешное восстановление отзывает другие сессии и открывает настройки для смены почты. Без кода требуется восстановить сам почтовый ящик.
- «Выйти со всех устройств» отзывает все сессии входа по почте, подтверждения, push-подписки и активные звонки. Для старого входа через Sites сначала требуется привязать почту. Привязанный аккаунт больше не принимает Sites-заголовки вместо почтовой сессии.
- Удаление требует свежего подтверждения, текста «УДАЛИТЬ» и отдельного согласия на удаление принадлежащих пользователю каналов. Личный контент, переписки, связи и интеграции удаляются. Чужие опубликованные посты сохраняются; будущие публикации удаляемого редактора в чужом канале отменяются. Ledger Stars и доказательства модерации сохраняют обезличенный ID; это не изменяет чужие балансы. Аккаунт администратора через этот интерфейс удалить нельзя.

Удаляется аккаунт **NoctGram**. Техническая запись пользователя у внешнего провайдера Supabase Auth остаётся: текущая интеграция не имеет административного ключа Supabase. Эта запись не восстанавливает удалённый профиль и не позволяет использовать отозванные сессии. Полное удаление такой записи требует отдельной настройки серверного доступа к Supabase Admin API.

## Антиспам и файлы

Лимиты хранятся в D1 и работают между экземплярами Worker: 5 постов/мин, 30 сообщений/мин, 15 комментариев/мин, 5 историй/мин, 3 канала/час, 8 жалоб/10 мин, 15 загрузок/мин. Реакции, подписки, поддержка и массовые изменения также ограничены. Счётчики привязаны к пользователю, а не каналу. Ответ 429 содержит `Retry-After`. Завершение звонка и отключение интеграций остаются доступны.

Полный multipart ограничивается до разбора, включая дополнительные части и запросы без `Content-Length`: максимум размера файла плюс 16 КиБ служебных данных. Разрешена ровно одна часть `file`. После превышения может быть отброшен небольшой ограниченный хвост потока (до 1 МиБ/250 мс) для корректного завершения локального HTTP-соединения; он не разбирается и не сохраняется. Принятый файл по-прежнему ограничен 25 МиБ, при регистрации — 5 МиБ.

Квота вложений — 512 МиБ/500 файлов на аккаунт, с атомарным резервированием до R2 PUT. У личной музыки отдельная квота 512 МиБ/500 файлов. Старые загрузки до уточнения размера через R2 HEAD консервативно учитываются как 25 МиБ.

`/api/jobs/run` выполняет ограниченные порции очистки. Неиспользуемые вложения удаляются не раньше 24 часов после загрузки. Учитываются все сохранённые ссылки: будущие и отменённые посты, скрытые профили, истёкший Premium и доказательства модерации. Истории сохраняются семь дней после истечения; доказательства не удаляются автоматически. Сначала файл атомарно переводится в `deleting`; триггеры запрещают его новое прикрепление. Ошибка R2 оставляет операцию для повторения. Музыкальные файлы имеют устойчивую очередь очистки и проверку действующих ссылок.

## Обновление и проверка

Нужна миграция `drizzle/0014_abandoned_nightshade.sql` **вместе с триггерами в конце файла**. Перед обновлением рабочей базы сделайте резервную копию. Существующей локальной базе миграция применяется один раз. При чистой установке администратора следует назначить конкретному проверенному ID серверной операцией; регистрация с подходящим юзернеймом не назначает роль.

Для прямого публичного Worker требуется `NOCT_AUTH_MODE=email`. Hybrid предназначен для локальной разработки/доверенного Sites proxy. Отправку писем проверяют существующие Supabase/SMTP настройки; платёжные сервисы эти изменения не включают.

Проверки: `npm run build`, `npm run lint`, `npx tsc --noEmit`; `tests/account-management.test.mjs`, `tests/administration.test.mjs`, `tests/upload-storage.test.mjs` используют SQLite в памяти. `tests/account-protection.integration.mjs` предназначен только для изолированного Worker на порту 8787 с mock-провайдером на 8791 и QA-фикстурами. Он проверяет реальные HTTP-маршруты, cookie, CSRF, загрузки, лимиты, выдачи и удаление. Тесты не отправляют настоящих писем.

Основа проверки восстановления: [OWASP — Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html), [Supabase — Email OTP](https://supabase.com/docs/guides/auth/auth-email-passwordless).
