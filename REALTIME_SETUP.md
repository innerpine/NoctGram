# Stories, аудиозвонки и уведомления

## Что уже работает локально

- Stories над лентой: текст, фото/видео, четыре фона, просмотр по порядку, пауза, список посмотревших для автора, удаление и жалобы. До 20 активных историй на аккаунт, срок — 24 часа. Видео в просмотрщике показывается до 30 секунд.
- Аудиозвонки один на один: кнопка телефона в диалоге, принятие/отклонение, микрофон, завершение и таймауты. Запрет личных сообщений, чёрный список и ограничения аккаунта действуют на звонки. Принимается только одно устройство. Запись разговоров не ведётся.
- Команда канала: владелец назначает администраторов и редакторов. Команда и очередь доступны из профиля канала.
- Отложенные посты: часы в редакторе, время от минуты до года вперёд. Очередь позволяет перенести или отменить публикацию. Поля даты показывают часовой пояс устройства; сервер хранит абсолютное время.
- Колокольчик: сообщения, звонки и новые посты подписок. Push включается по нажатию на устройстве, также доступен в «Редактировать → Приватность».

| Действие | Владелец | Администратор | Редактор |
| --- | --- | --- | --- |
| Публиковать от имени канала | Да | Да | Да |
| Редактировать имя, описание и изображения | Да | Да | Нет |
| Изменять юзернеймы и состав команды | Да | Нет | Нет |
| Закреплять и удалять опубликованные посты | Да | Да | Нет |
| Управлять очередью | Вся | Вся | Только свои посты |

Отзыв участника отменяет его ещё не опубликованные посты. Повторное назначение их не восстанавливает. Новое ограничение автора/канала отменяет затронутые будущие публикации. Опубликованные посты канала сохраняются после ухода редактора. В очереди отменённые строки помечены и не имеют действий.

## Локальный запуск

Для существующей базы с миграциями 0000–0006 применить **только новую** миграцию:

```powershell
npx wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0007_organic_slipstream.sql
npm ci
npm run setup:realtime
npm run dev
```

Для новой пустой базы следовать CONTRIBUTING.md и применить все миграции один раз. В текущем рабочем окружении миграция 0007 уже применена.

В другом терминале:

```powershell
npm run dev:jobs
```

`setup:realtime` создаёт VAPID-ключи и секрет фоновых задач в игнорируемом `.env`; существующие ключи сохраняются. После изменения `.env` перезапустить сервер. Не запускать несколько локальных обработчиков без необходимости.

Пост становится видимым по SQL-времени без открытой вкладки и без фоновой задачи. Обработчик нужен для доставки push и подготовки уведомлений, когда сайт никто не открывает. Он обращается к `/api/jobs/run` каждые 10 секунд. Пока компьютер или сервер выключен, доставки нет; после запуска очередь продолжает работу.

## Общий сервер для тебя и друга

Два отдельных localhost имеют разные базы. Чтобы звонить друг другу и видеть одну ленту, нужны **один HTTPS-адрес, одна рабочая D1 и одно R2-хранилище**. GitHub синхронизирует код, а не аккаунты и сообщения. Этот пакет изменений сам не публикует сайт.

На сервер перенести нужные переменные окружения из `.env` через менеджер секретов хостинга:

| Переменная | Назначение |
| --- | --- |
| `NOCT_VAPID_PUBLIC_KEY` | Публичный ключ push, выдаётся браузеру |
| `NOCT_VAPID_PRIVATE_KEY` | Секрет подписи push, только сервер |
| `NOCT_VAPID_SUBJECT` | Контактный `mailto:` или HTTPS-адрес проекта |
| `NOCT_JOBS_SECRET` | Секрет доступа фонового обработчика |
| `NOCT_STUN_URLS` | STUN-адреса через запятую, по умолчанию Google STUN |
| `NOCT_TURN_URLS` | Адреса TURN через запятую |
| `NOCT_TURN_SECRET` | Shared secret coturn REST, только сервер |

Для надёжной связи между разными сетями нужен **TURN**, например coturn с `use-auth-secret` и `static-auth-secret`, совпадающим с `NOCT_TURN_SECRET`. Сервер выдаёт браузеру временные credentials на 3 часа. Shared secret клиенту не передаётся. Без TURN звонок может установиться напрямую, но некоторые NAT/мобильные сети не соединятся. Документация: [WebRTC TURN](https://webrtc.org/getting-started/turn-server), [coturn REST credentials](https://github.com/coturn/coturn/blob/master/README.turnserver).

## Фоновые задачи на хостинге

Подготовлен отдельный Cloudflare Worker `jobs/worker.ts` с запуском каждую минуту. После развёртывания основного приложения задать для него `NOCTGRAM_ORIGIN` (общий HTTPS-адрес) и секрет `NOCT_JOBS_SECRET`, совпадающий с секретом приложения. Запустить worker по `jobs/wrangler.jsonc` согласно процессу развёртывания проекта. Это отдельное развёртывание; в локальной разработке достаточно `npm run dev:jobs`.

Другой планировщик также может выполнять `POST <общий-адрес>/api/jobs/run` с заголовком `Authorization: Bearer <NOCT_JOBS_SECRET>` раз в минуту. Адрес должен быть доступен планировщику: внешний шлюз авторизации не должен перехватывать этот маршрут. Сам маршрут всегда проверяет секрет. Не размещать секрет в URL.

Доставка идёт через постоянную очередь, с атомарным захватом и повторами при ошибке. Уведомления о звонках имеют приоритет, уже завершённые звонки не отправляются. Устаревшие подписки с ответом 404/410 удаляются. Подписка привязана к браузеру и аккаунту, действует до 30 дней; после истечения её можно включить снова. Выход отключает push текущего браузера. Текст личного сообщения в push не включается. Как у любой сетевой очереди, потеря ответа провайдера после успешной доставки может привести к повтору; одинаковый tag заменяет прежнее уведомление на устройстве.

## Проверка устройств перед запуском

1. Открыть общий HTTPS-адрес в двух браузерах под разными аккаунтами.
2. Разрешить микрофон, позвонить и проверить звук в обе стороны, отключение микрофона, отклонение, выход и закрытие вкладки. Повторить через разные сети с TURN.
3. Включить push по кнопке, свернуть/закрыть вкладку, отправить сообщение со второго аккаунта. Проверить переход из уведомления и прекращение доставки после выхода.
4. На iPhone/iPad открыть приложение, добавленное на экран «Домой»; поддержка зависит от версии ОС и настроек уведомлений. [Требования WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
5. Запланировать пост, закрыть вкладку, открыть после срока другим аккаунтом. Проверить права редактора и отзыв его доступа.

Автоматические тесты проверяют API и переходы состояний; они не подтверждают реальный звук между двумя устройствами или системный popup push. Service worker не кэширует личные API и сообщения. Просроченные stories скрываются из чтения; очистка файлов из R2 и политика хранения исторических записей остаются отдельной задачей эксплуатации.

Тест меняет время только своих записей в этой тестовой базе для проверки публикации и истечения срока без ожидания. Не направлять его на рабочий сервер.

```powershell
node tests/realtime.integration.mjs
```
