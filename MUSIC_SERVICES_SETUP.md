# Подключение музыкальных аккаунтов

Страница: `/music/services` или «Музыка → Подключить музыкальные сервисы». Она повторяет сценарий из предоставленного примера Dotify: выбор сервиса, вход, проверяемый статус аккаунта, личные плейлисты и импорт. Используется существующая авторизация Noctgram; музыкальный аккаунт привязывается к уже вошедшему пользователю.

## Готовые адаптеры

| Сервис                     | Вход                                    | Личные плейлисты                                                       | Поиск                                 | Прослушивание                                                       |
| -------------------------- | --------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------- |
| SoundCloud                 | OAuth с PKCE и серверным секретом       | Получение списка с догрузкой, сохранение в личной коллекции            | Треки                                 | Публичные ссылки через официальный виджет, приватные — в SoundCloud |
| Spotify                    | OAuth с PKCE                            | Получение списка с догрузкой, сохранение метаданных в личной коллекции | Не добавлен                           | Наш интерфейс + официальный Web Playback SDK, Premium               |
| Яндекс Музыка              | Токен своего аккаунта, экспериментально | Синхронизация до 100 плейлистов, чтение состава до 1000 позиций        | Поиск записи в SoundCloud по названию | Аудио Яндекса не подключено                                         |
| YouTube, VK Музыка, Deezer | Адаптеры не реализованы                 | Недоступно                                                             | Недоступно                            | Недоступно внутри Noctgram                                          |

OAuth-импорт сохраняет ссылку, название, обложку и число треков выбранного плейлиста в личной коллекции. Аудио и состав плейлиста остаются у сервиса. Это не скачивание аудио и не локальная копия каждого трека. Импортированные данные не попадают в общие открытия, музыкальные чарты или профили других пользователей. OAuth-адаптер Spotify используется для переноса метаданных пользовательских плейлистов. См. [Spotify Developer Policy](https://developer.spotify.com/policy), раздел III.

Отдельно в `/music` можно добавить публичную ссылку на трек Spotify и прикрепить собственный аудиофайл. Этот сценарий не требует музыкального аккаунта, Premium или OAuth: сведения берутся из публичных метаданных, а воспроизводится личный файл из R2. Подробнее: [MUSIC.md](MUSIC.md).

## Однократная настройка владельцем

`Client ID` идентифицирует приложение Noctgram. Он не подтверждает вход пользователя. Для SoundCloud и Spotify каждый пользователь входит на официальной странице сервиса и разрешает доступ своему аккаунту. Экспериментальный адаптер Яндекса отдельно принимает токен собственного аккаунта, не пароль.

1. Применить **новую** миграцию `drizzle/0008_polite_adam_destine.sql` к базе, где уже выполнены 0000–0007. Для пустой базы выполнить все миграции по порядку. Повторно старые миграции не выполнять.
2. Заполнить переменные в личном `.env` по `.env.example`. Для размещённого проекта задать их как runtime secrets. `.env` и ключи не добавлять в Git.
3. Зарегистрировать точные callback URL в кабинетах музыкальных сервисов. Открывать приложение на том же origin, который указан в callback. Код проверяет совпадение и не использует произвольный Host для перенаправления.
4. Перезапустить локальный сервер, открыть `/music/services` и нажать «Подключить». Кнопка станет доступна, когда сервер увидит все необходимые настройки.

### Шифрование

`MUSIC_TOKEN_KEY` — отдельные 32 случайных байта в виде 64 шестнадцатеричных символов. В текущей локальной `.env` ключ уже создан. На другом компьютере с новой базой нужен собственный ключ. Существующую базу подключений необходимо переносить вместе с её ключом через защищённое хранилище; замена ключа потребует повторного подключения аккаунтов.

Токены доступа, обновления и PKCE-verifier шифруются AES-256-GCM с привязкой к пользователю, сервису и назначению. OAuth state связан с текущей сессией Noctgram и HttpOnly-cookie браузера, действует 10 минут, используется один раз. Краткоживущий Spotify access token передаётся только авторизованному браузеру через POST `playback-token` с проверкой Origin и `private, no-store`, затем официальному SDK и Spotify Web API. Он остаётся в памяти активного устройства; refresh token из сервера не выходит. В URL и localStorage токенов нет.

### SoundCloud

Публичные отдельные треки воспроизводятся через официальный SoundCloud API на одном постоянном `<audio>`, без перезагрузки виджета при смене песни. Safari/iOS получает HLS напрямую, Chrome и другие браузеры используют лениво загружаемый HLS.js. Очередь Noctgram, перемотка, громкость и совместное прослушивание используют этот же аудиоэлемент. Ссылки на готовые плейлисты SoundCloud пока воспроизводятся через официальный виджет.

Для этого режима нужны `SOUNDCLOUD_CLIENT_ID`, `SOUNDCLOUD_CLIENT_SECRET`, `MUSIC_TOKEN_KEY` и миграция `0029_music_app_tokens.sql`. Для уже существующей базы применяется только новая миграция, без повторного импорта данных. Авторизация приложения использует Client Credentials: слушателям не требуется собственный Artist Pro или отдельный вход в SoundCloud. Redirect URI ниже относится к дополнительному подключению личного аккаунта и импорту плейлистов.

Access/refresh-токены приложения хранятся зашифрованными в D1 отдельно от пользовательских OAuth-подключений. Обновление защищено общей блокировкой; после неопределённого сетевого сбоя одноразовый refresh token не повторяется. Клиентские ключи и OAuth-токены не выдаются браузеру. Авторизованный маршрут `/api/music/soundcloud?action=stream&url=...` перенаправляет на временный CDN-поток SoundCloud; аудио не копируется в R2. API не подменяет недоступные треки превью и не воспроизводит приватные записи.

Если API не настроен, остаётся прежний виджет. Его `load()` перезагружает документ даже при сохранении DOM-элемента iframe, поэтому этот запасной режим не гарантирует мобильный автопереход между отдельными ссылками. Эмуляция iPhone на Windows не подтверждает поведение настоящего Safari: требуется проверка звука на физическом устройстве.

Регистрация приложения и актуальные требования описаны в [официальном API Guide](https://developers.soundcloud.com/docs/api/guide#authentication). На момент реализации SoundCloud указывает Artist Pro как условие получения API-ключей.

```dotenv
SOUNDCLOUD_CLIENT_ID=
SOUNDCLOUD_CLIENT_SECRET=
SOUNDCLOUD_REDIRECT_URI=http://localhost:3000/api/music/services/soundcloud/callback
```

В размещённом приложении вместо `http://localhost:3000` нужен точный HTTPS-origin Noctgram. Все запросы обмена кода и обновления токена идут с сервера на `secure.soundcloud.com`; данные аккаунта запрашиваются с `api.soundcloud.com`. Обновления выполняются под блокировкой в D1: одноразовый refresh token не расходуется одновременно несколькими вкладками. Если исход обновления неизвестен, требуется повторный вход.

### Spotify

Создать приложение в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) и зарегистрировать callback. Используется [Authorization Code with PKCE](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow) с разрешениями `playlist-read-private playlist-read-collaborative streaming user-read-email user-read-private user-modify-playback-state`. Секрет клиента для выбранного PKCE-потока не используется. Старые подключения необходимо обновить кнопкой «Обновить разрешения плеера».

```dotenv
SPOTIFY_CLIENT_ID=
SPOTIFY_REDIRECT_URI=http://127.0.0.1:3000/api/music/services/spotify/callback
```

Для Spotify локально открыть Noctgram через `http://127.0.0.1:3000`, войти в Noctgram на этом адресе и затем подключить Spotify. `localhost` не подходит по [правилам redirect URI Spotify](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri). Публичное приложение использует HTTPS. Доступ реальных пользователей также зависит от режима приложения и разрешений Spotify; конфигурация клиента сама по себе не отменяет эти ограничения.

## Отключение и пределы

Каждый слушатель Spotify должен иметь свой Premium. SDK получает и расшифровывает поток в браузере; аудио Spotify не проходит через R2 или Worker Noctgram. Пауза, громкость, перемотка и повтор управляют официальным SDK. При запрете автозапуска пользователь нажимает Play; нужен браузер с поддержкой EME. Отсутствие Premium, недоступный трек, ошибка авторизации или передача на другое устройство отображаются в плеере.

[Изменения Spotify development mode 2026](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide): для нового приложения владелец должен иметь Premium, доступ обычно ограничен пятью разрешёнными пользователями. Это не готовый доступ для тысяч пользователей. Поле `product` из `/me` удалено, поэтому Premium проверяет SDK; число треков плейлиста читается из нового `items.total` с поддержкой старого `tracks.total`.

Spotify SDK не отправляет события в чарт Noctgram. В автоматической очереди SDK выбираются только Spotify-треки. [Spotify Developer Policy](https://developer.spotify.com/policy) ограничивает метрики на основе Spotify Content и совмещение Spotify Streaming с другими сервисами. Перед публичным запуском такого многосервисного приложения необходимо согласовать его использование с Spotify; работа SDK в тестах сама по себе не даёт разрешение на массовый релиз.

### Яндекс Музыка

Используется экспериментальный протокол метаданных, сверенный с исходниками [yandex-music-api](https://github.com/MarshalX/yandex-music-api). Это не официальный открытый SDK Яндекс Музыки и не гарантия стабильности сервиса. Токен своего аккаунта вводится в `/music/services` на вкладке Яндекс; обычный токен Яндекс ID без доступа к Музыке может не подойти. Noctgram не извлекает токены из браузера и не выдаёт себя за чужое приложение. Не отправляйте токен в чат или Git.

После проверки `/account/status` сохраняется зашифрованное подключение. «Синхронизировать плейлисты» обновляет названия, обложки и число треков, удаляет исчезнувшие плейлисты. Состав читается заново при открытии плейлиста. Периодической фоновой синхронизации нет. Данные видны только владельцу; можно перейти к поиску названия в SoundCloud, но совпадение записей не подменяется автоматически. Аудио Яндекса не воспроизводится и не скачивается. Токен не обновляется автоматически: после отказа требуется новое подключение. Для этого этапа достаточно `MUSIC_TOKEN_KEY`, новых миграций нет.

### Поиск SoundCloud

Поиск вынесен также на `/music`, рядом с формой ссылки. Требуется настроенное приложение SoundCloud и подключение пользователя; ключи нельзя заменить случайным Client ID. Поиск запрашивает до 20 доступных для воспроизведения записей. Есть сохранение, длительность, обработка пустого результата, отмена устаревших запросов и переход к настройке подключения. Прослушивание уже известной публичной ссылки через виджет по-прежнему не требует такого подключения.

«Отключить» удаляет сохранённые в Noctgram токены, незавершённые попытки входа и импортированные плейлисты выбранного сервиса. Запоздавшие callback и обновления токена не восстанавливают отключённый аккаунт. Read-only может удалить подключение. Выданное разрешение на стороне провайдера при необходимости также отзывается в настройках самого SoundCloud/Spotify; отдельного удалённого отзыва из Noctgram пока нет.

YouTube, VK и Deezer остаются недоступными состояниями. Переключатель локального/удалённого выполнения из Dotify не добавлен: запросы аккаунта выполняет сервер Noctgram. Яндекс принимает только предоставленный пользователем токен его аккаунта; ручной ввод чужих client IDs не реализован.

## Проверки

```powershell
npx tsc --noEmit
npm run lint
npm run build
node tests/music-services.test.mjs
node tests/spotify-player.test.mjs
node tests/music-lyrics-search.test.mjs
# With the isolated local Worker described in MUSIC.md:
node tests/music-connections.integration.mjs
```

Тест выполняет настоящий код адаптеров и SQL миграций в изолированной SQLite-базе. Ответы SoundCloud/Spotify/Яндекса заменены тестовыми, реальные аккаунты не используются. Проверяются PKCE, шифрование, привязка владельца/cookie, повтор state, скрытие refresh tokens, личные импорты, пагинация, refresh и отключение во время запроса. Дополнительно проверяются Spotify scopes после обновления, отсутствие токена у другого пользователя, фильтрация SoundCloud preview/private и Яндекс: обновление/удаление плейлистов, токен с ошибкой, запрет подмены пути и отключение во время подключения/синхронизации. Отдельный тест SDK подменяет устройство и проверяет управление, Premium/autoplay errors, ручную паузу у конца трека и отмену запоздавшего токена.

HTTP-тест собранного Worker проверяет авторизацию, ограничения аккаунта, Origin, `no-store` и отсутствие рабочего токена при ненастроенном сервисе. Для ранней проверки Origin передаётся пустой POST: у локального Windows workerd есть проблема с ответом до чтения тела. Запросы с допустимым Origin проверяются с JSON.

Реальный OAuth-вход, доступность конкретных плейлистов и браузерное воспроизведение требуют проверки после настройки зарегистрированных приложений. Успешные автоматические тесты не означают, что реальные аккаунты уже подключены.
