# Музыка в Noctgram

Раздел `/music` встроен в существующий Noctgram: навигация, лента и переписка используют те же компоненты и дизайн. Глобальный `MusicProvider` в корневом layout сохраняет воспроизведение при переключении разделов.

## Что работает

- Публичные канонические ссылки на трек или плейлист SoundCloud. Название, автор и обложка запрашиваются сервером через официальный [oEmbed](https://developers.soundcloud.com/docs/oembed); аудио воспроизводит официальный [Widget API](https://developers.soundcloud.com/docs/api/html5-widget). API-ключ для этого способа не нужен. HTML из oEmbed не вставляется в страницу.
- Сохранённые ссылки в D1, максимум 100 на аккаунт. SoundCloud публикуется в «Открытиях»; Spotify с личным аудиофайлом остаётся в коллекции владельца. Открытия учитывают ограничения аккаунтов и личные блокировки.
- Собственный интерфейс Noctgram: компактная панель и большой плеер по нажатию на обложку или название. Большой плеер использует затемнённую размытую обложку как фон, показывает очередь и текст песни. Escape и стрелка вниз сворачивают окно, не пересоздавая аудиодвижок. Есть пауза, предыдущий/следующий трек, выбор записи из очереди, перемотка, громкость и отключение звука. Для плейлиста переход к выбранной записи использует `Widget.skip`.
- Настройки большого окна: затемнение, размытие фона, размер текста, размытие соседних строк, анимация и сдвиг текста ±5 секунд. Оформление сохраняется локально на устройстве; сдвиг сбрасывается при смене трека. Системное `prefers-reduced-motion` имеет приоритет над анимацией.
- Настройки открываются правой кнопкой мыши в большом плеере или Shift+F10. Повторный правый клик закрывает панель, включая клик внутри неё. Панель появляется у курсора; кнопка в правом верхнем углу удалена. При переключении «Обложка / Текст / Очередь» сетка плавно меняет ширину колонок, обложка — положение и размер, а боковые панели меняются с затуханием. Панели сохраняются в DOM, неактивные исключены из фокуса через `inert`.
- В компактном плеере есть ползунок громкости, процент и выключение/возврат звука. Громкость сохраняется на устройстве. Когда следующего доступного трека нет, повторяется текущий, в том числе последний трек SoundCloud-плейлиста. Очередь SoundCloud/личных файлов пропускает Spotify без файла; официальный Spotify SDK последовательно выбирает только Spotify-записи.
- Поиск SoundCloud по названию или исполнителю прямо на `/music`: обложки, длительность, прослушивание и сохранение. Для поиска нужно настроенное OAuth-подключение SoundCloud; добавление известной публичной ссылки остаётся без этого требования.
- Spotify Web Playback SDK воспроизводит отдельные треки в существующем интерфейсе Noctgram с Premium на аккаунте слушателя. Пауза, перемотка, громкость, очередь и повтор работают через SDK; звук не сохраняется на нашем сервере. Треки с прикреплённым личным файлом по умолчанию играют файл, отдельная кнопка выбирает Premium. SDK-прослушивания не входят в чарт. Ошибки аккаунта и браузера отображаются без подмены другим источником.
- Добавление трека Spotify по канонической ссылке (включая `/intl-xx/track/...`). Сервер получает название и обложку через oEmbed, исполнителя и длительность — из публичных meta-тегов страницы. Скрипты страницы не выполняются, её аудио не извлекается. Если метаданные недоступны, добавление возвращает понятную ошибку.
- К карточке Spotify можно прикрепить собственный MP3/WAV/OGG/FLAC до 25 МБ. Файл сохраняется в R2 и воспроизводится обычным HTMLAudioElement с громкостью, перемоткой, очередью и поиском текста по метаданным. Premium и OAuth для этого сценария не нужны. Это загрузка файла пользователем, а не скачивание защищённого аудио из Spotify. Серверный файл доступен только владельцу коллекции; при замене и удалении прежний объект удаляется. Проверяются формат, размер, авторизация и HTTP Range для перемотки. При включённом участии эти прослушивания входят в общий чарт; чужой аудиофайл при этом не становится доступным.
- Текст запрашивается у [LRCLIB](https://lrclib.net/docs) только для открытой вкладки «Текст», по названию, автору и длительности текущего трека. Аккаунт и токены не передаются. Есть синхронизация по строкам LRC, переход к строке по нажатию, обычный текст без таймингов и состояния отсутствия текста/инструментала/ошибки. Синхронизация по словам и перевод не имитируются. Кэш ограничен 30 результатами на 10 минут в памяти вкладки; отменяются запросы к предыдущему треку, учитывается `Retry-After`. Автор загрузки SoundCloud может отличаться от исполнителя, поэтому текст находится не для каждой записи.
- Белого блока и отдельных кнопок перехода в SoundCloud нет. Небольшая подпись источника остаётся ссылкой на запись ([требования атрибуции](https://developers.soundcloud.com/docs/api/guide#streaming-tracks)). Аудио по-прежнему воспроизводит один скрытый iframe через официальный Widget API, а не собственный сервер аудиопотоков. Ограничения доступности, регионов и автозапуска сохраняются; при запрете автозапуска пользователь нажимает Play в Noctgram. Совместимость этого запуска с конкретными браузерами требует ручной проверки.
- Карточка первой подходящей ссылки в публикации и сообщении. Чтение сообщения не загружает сторонний embed: обращение начинается после нажатия слушателя.
- Топ 30 треков, исполнителей и слушателей за сегодня (с 00:00 UTC), последние 7 или 30 дней. Собственное место и число зачётов доступны и за пределами первой тридцатки. Участие выключено по умолчанию. 30 секунд продвижения аудио дают один зачёт на трек/участника/сутки UTC; переходы по ссылке не учитываются. Для SoundCloud исполнитель — автор загрузки; записи разных сервисов не объединяются автоматически.
- Общий счётчик для Widget и HTMLAudioElement исключает паузы, перемотку и скачки времени при приостановке вкладки. Статус виден в компактном плеере и ведёт в чарты. Повтор короткой песни сохраняет накопленные секунды; повтор уже засчитанного трека не накручивает рейтинг. При наступлении новых суток создаётся новая сессия. Сервер ограничивает зачёт прошедшим временем, одной активной сессией и уникальной записью на день. Повторные/одновременные события идемпотентны. При выключении участия удаляются сессии и история слушателя. Read-only может отозвать согласие.
- Статистика отправляет одно подтверждение после порога вместо записи каждые пять секунд; сетевые ошибки имеют ограниченный повтор. Чарт обновляется раз в минуту в видимой вкладке, после собственного зачёта и вручную. `home?charts=0` не вычисляет рейтинги; `period=today|7|30` выбирает период. Ответы личные, без общего кэша, с существующими ограничениями видимости профилей.

## Границы

Страница `/music/services` содержит OAuth-адаптеры SoundCloud и Spotify, а также экспериментальную синхронизацию Яндекс Музыки по токену собственного аккаунта. Для настоящего OAuth-входа владелец должен настроить зарегистрированные приложения: [MUSIC_SERVICES_SETUP.md](MUSIC_SERVICES_SETUP.md). Spotify сохраняет карточки плейлистов, а отдельные треки проигрывает через официальный SDK. Яндекс обновляет список плейлистов и читает состав при открытии, позволяет перейти к поиску записи в SoundCloud; аудио Яндекса пока не подключено. YouTube, VK Музыка и Deezer остаются недоступными.

Поиск LRCLIB сначала пробует исходное название, затем название без `prod.`/служебных видеопометок, затем полнотекстовый поиск. Кандидаты проверяются по исполнителю, версии и длительности (±2,5 секунды), синхронный текст имеет приоритет. Ошибки точного поиска не мешают fallback; 429 и отмена останавливают цепочку. Есть повтор поиска текста. Регрессия «Vendetta! (prod. Mupp) / Sadfriendd / 107 секунд» проверена на живом API — найдено 49 синхронных строк.

События публичного виджета не являются криптографическим доказательством прослушивания: модифицированный клиент может имитировать их с допустимой скоростью. Этот рейтинг подходит для MVP; для наград с материальной ценностью нужны дополнительные меры. Браузерное воспроизведение, фоновые ограничения мобильных ОС и реальная анимация требуют отдельной ручной проверки. Данные автоматических API-тестов не являются реальными прослушиваниями.

Метаданные кэшируются при первом добавлении. Если запись позже стала недоступной, плеер покажет ошибку с повторной попыткой. Частные ссылки, `secret_token`, сокращённые ссылки и неподдерживаемые адреса отклоняются. Конструктор плейлистов и сквозное сопоставление одинаковых песен между сервисами не реализованы.

## Файлы

- `app/music-panel.tsx`, `app/music.css`: раздел и оформление по `DESIGN.md`.
- `app/music-provider.tsx`, `lib/soundcloud-widget.ts`: жизненный цикл единственного плеера.
- `app/music-player-view.tsx`, `app/music-player.css`, `lib/music-player.ts`: собственный интерфейс, оформление и синхронизация текста.
- `app/music-audio-upload.tsx`, `app/api/music/audio/[id]/route.ts`, `lib/music-audio.ts`: личные аудиофайлы и поток с поддержкой диапазонов.
- `lib/spotify-metadata.ts`: ограниченное чтение публичных сведений о треке Spotify.
- `lib/spotify-player.ts`: официальный SDK, транспорт, короткоживущий токен в памяти устройства и очистка при закрытии.
- `lib/music-lyrics-search.ts`: нормализация и выбор подходящей записи LRCLIB.
- `app/music-search.tsx`: поиск названия в SoundCloud и сохранение найденного трека.
- `app/music-yandex.tsx`, `app/api/music/yandex/route.ts`, `lib/yandex-music.ts`: экспериментальное подключение Яндекса и синхронизация метаданных.
- `app/music-link-card.tsx`: компактные карточки ссылок.
- `app/api/music/route.ts`: метаданные, коллекции, участие, события и чарты.
- `lib/music-links.ts`: строгая граница допустимых ссылок.
- `lib/music-listening.ts`: общая логика зачёта и выбор следующей доступной песни.
- `MUSIC_SCALING.md`: решение по R2, расчёт объёмов, текущие ограничения и возможности Spotify.
- `db/schema.ts`, `drizzle/0007_perfect_radioactive_man.sql`: новые таблицы, существующие миграции сохранены.

## Локальная проверка

Обычный запуск описан в `CONTRIBUTING.md`. После получения этой ветки применить только ещё не выполненные миграции 0007, 0008 и 0009 к существующей локальной базе. Миграция `0009_ambiguous_polaris.sql` добавляет личные аудиофайлы и длительность в метаданных трека. Для новой базы — все миграции в порядке имён. SoundCloud embed и Spotify с собственным файлом не требуют нового секрета; OAuth-аккаунты настраиваются отдельно.

```powershell
npx tsc --noEmit
npm run lint
npm run build
node tests/music-links.test.mjs
node tests/music-player.test.mjs
node tests/music-audio.test.mjs
node tests/music-listening.test.mjs
node tests/music-services.test.mjs
node tests/spotify-player.test.mjs
node tests/music-lyrics-search.test.mjs
# Optional: real LRCLIB metadata lookup, no lyric text printed or saved.
node tests/music-lyrics-search.test.mjs --live
```

Для интеграционного теста создать отдельную локальную базу (каждую миграцию выполнить в ней один раз):

```powershell
Get-ChildItem drizzle -Filter *.sql | Sort-Object Name | ForEach-Object {
  npx wrangler d1 execute DB --local --config wrangler.local.json --persist-to work/music-qa --file $_.FullName
  if ($LASTEXITCODE -ne 0) { throw "Migration failed" }
}
npx wrangler d1 execute DB --local --config wrangler.local.json --persist-to work/music-qa --file tests/fixtures/music.sql
npx wrangler d1 execute DB --local --config wrangler.local.json --persist-to work/music-qa --file tests/fixtures/music-charts.sql
npx wrangler dev --config dist/server/wrangler.json --port 8787 --persist-to work/music-qa
```

В другом терминале: `node tests/music.integration.mjs`. Тест откажется работать с нелокальным URL и занимает около 32 секунд из-за проверки серверного времени. Искусственные фикстуры применять только к `work/music-qa`, никогда к размещённой базе. Проверяются авторизация/ограничения, собственность коллекции, отключённый по умолчанию учёт, чужие и устаревшие сессии, ранние/повторные/одновременные события и удаление истории при отзыве согласия.

Изменение исходников в GitHub само по себе не публикует приложение и не переносит локальные данные. Для существующего Sites-проекта нужны доступ владельца и применение миграции при согласованном размещении.

`node tests/music-audio.integration.mjs` использует тот же изолированный Worker. Он проверяет реальный импорт публичных метаданных Spotify, загрузку синтетического WAV, отсутствие чужого доступа, полное/частичное чтение, замену и удаление файла. Тест не скачивает аудио Spotify и не создаёт настоящих прослушиваний. Автоматическая проверка HTTP/байтов не заменяет ручную проверку звука и анимаций в браузере.

Тест аудио также проверяет серверный зачёт личного файла после 30 секунд, запрет зачёта чужого файла и отсутствие доступа к нему через чарт. Для ранних отказов до чтения тела он использует пустой POST: Windows workerd может оборвать multipart-загрузку при раннем ответе, а локальный прокси ошибочно описывает это как перезапуск Worker. Передача, формат и диапазоны проверяются отдельными запросами с реальными синтетическими байтами.

`node tests/music-charts.integration.mjs` проверяет границы периодов, личное место за топ-30 и облегчённый запрос без агрегаций. Для текущего обновления новых миграций нет.
