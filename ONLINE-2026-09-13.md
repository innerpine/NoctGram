# Administrator online statistics

The administration dialog has separate Users and Online tabs. Online shows
current active accounts, registered personal profiles, and the peak and average
online count for the last 24 hours. The graph offers the last hour by minute,
24 hours by hour, and seven days by hour. Hourly values are averages and peaks
of minute samples, not a sum or a count of distinct visitors throughout the hour.

Presence reuses `users.lastSeen`: a completed, undeleted personal account with
authenticated activity in the last two minutes counts once, regardless of tabs
or devices. Active account blocks exclude that account. Anonymous requests do
not update presence. Hidden presence is included only in aggregate counts; this
feature exposes no names, IP addresses or per-user history.

The public Worker runs each minute. Its existing maintenance tasks continue
every fifth minute; other invocations call the same secret-protected jobs route
with `onlineOnly=1`. Snapshot retries within one minute do not overwrite data.
Samples are retained for 30 days. No historical data is inferred or backfilled;
missing samples remain graph gaps, including periods before deployment.

The admin API requires administrator access and returns private, no-store
responses. The panel refreshes every 30 seconds only while mounted and visible,
has a request timeout, cancels obsolete requests and prevents overlapping polls.
Chart code is loaded on opening the Online tab. Queries use the presence index
and bounded history ranges. Saving counts adds no new requests from user pages.

## Deployment

Apply only `drizzle/0043_admin_online.sql` to the existing public database after
validating a fresh backup. It adds `online_samples` and the `users_last_seen`
index without modifying existing rows. Run `PRAGMA optimize` afterwards.
Set the public Worker's cron to `* * * * *`; keep the existing jobs secret,
database, bucket, authentication and other runtime settings unchanged.

Validate real SQL aggregation, role restrictions, empty history versus zero
online, presence expiry, cron idempotency, retention, query plan, hourly averages
and five-minute maintenance cadence. The isolated tests use synthetic accounts
and never send test traffic as real users to production.
