# Восстановление бюджета private preview

Только режим `NOCT_AUTH_MODE=access`: общий накопительный лимит загрузок — 3 GiB, общие месячные лимиты — 10 000 операций записи и 200 000 чтений. Дополнительно один аккаунт может потратить 512 MiB загрузок за срок preview и 2 000 операций загрузки за месяц. Удаление черновика или файла не возвращает накопительный бюджет. Ошибки/повторы консервативно учитываются; если позднее сработал общий лимит, уже зарезервированная доля пользователя также остаётся потраченной.

Счётчики пользователя начинают действовать с этого обновления; ранее потраченные байты остаются в существующем общем счётчике. Сервер передаёт в R2 wrapper подтверждённый `userId`, а не значение multipart/JSON. Анонимная запись в preview запрещена.

## Проверка владельцем

Используйте административный доступ к правильной D1 и сначала проверьте расход/счета Cloudflare. Для локальной базы применяется `wrangler.local.json` и `--local`; удалённую базу выбирайте явно по её рабочей конфигурации. Не копируйте локальные данные поверх удалённых.

Прочитайте только нужные счётчики:

```sql
SELECT key,count,expiresAt FROM auth_limits
WHERE key='preview:r2:uploaded-bytes'
   OR key='preview:r2:user-uploaded-bytes:URL_ENCODED_USER_ID'
   OR key='preview:r2:user-write:URL_ENCODED_USER_ID:YYYY-MM';
```

Замените `URL_ENCODED_USER_ID` результатом `encodeURIComponent` для проверенного внутреннего ID, а `YYYY-MM` — текущим месяцем UTC. Не используйте отображаемое имя. Сначала выясните причину исчерпания и остановите злоупотребление; сохраните дату, причину и прежние значения в журнале эксплуатации.

## Возврат доступа одному пользователю

Владелец может разрешить новую пользовательскую долю, если общий бюджет ещё не исчерпан. Обновляйте только конкретный счётчик с защитой от изменения после проверки:

```sql
UPDATE auth_limits SET count=0
WHERE key='preview:r2:user-uploaded-bytes:URL_ENCODED_USER_ID'
  AND count=EXPECTED_PREVIOUS_COUNT;
```

При необходимости аналогично сбросьте конкретный ключ `preview:r2:user-write:URL_ENCODED_USER_ID:YYYY-MM`. Подставляйте предварительно прочитанное целое значение. Ноль изменённых строк означает, что счётчик изменился: перечитайте и пересмотрите решение, не убирайте условие. Это ручная административная операция, пользовательского API сброса нет.

**Не сбрасывайте общий `preview:r2:uploaded-bytes` и не удаляйте все `preview:r2:*` ключи.** Сброс доли одного пользователя не увеличивает общий лимит и не обходит его. Если 3 GiB израсходованы, автоматическое возобновление загрузок невозможно: владелец должен отдельно утвердить следующий ограниченный бюджет после проверки реального расхода и изменить лимит в конфигурации/коде. Для продолжения обычной эксплуатации используйте рассчитанные лимиты полноценного хостинга, а не отмену защитного ограничения.
